# PortWatch VI → Telegram

Присылает новые новости с https://portwatch-vi.xyz в Telegram. Работает на
серверах GitHub, поэтому компьютер может быть выключен.

## Как это устроено

- Сайт отдаёт RSS: `https://portwatch-vi.xyz/news/feed.xml`.
- GitHub Actions раз в 20 минут запускает `feedbot.py`.
- Скрипт читает ленту, сравнивает с `state.json` (что уже отправлено) и шлёт
  только новые записи.
- После отправки `state.json` коммитится обратно в репозиторий, чтобы при
  следующем запуске не повторяться.
- Первый запуск ничего не спамит: он запоминает текущую ленту и присылает одно
  сообщение «уведомления включены».

## Что нужно один раз настроить

1. Создать бота: в Telegram написать **@BotFather** → `/newbot` → придумать имя
   и username (должен заканчиваться на `bot`). Он выдаст токен вида
   `123456789:AA...`.
2. Нажать у своего бота **Start** (иначе он не сможет вам писать).
3. Узнать свой chat id: написать **@userinfobot** — он ответит числом.
4. В репозитории: Settings → Secrets and variables → Actions → New repository
   secret:
   - `TELEGRAM_TOKEN` — токен из пункта 1;
   - `TELEGRAM_CHAT_ID` — число из пункта 3.
5. Actions → «PortWatch VI to Telegram» → Run workflow. Через минуту придёт
   сообщение «уведомления включены».

## Проверить локально

```bash
python feedbot.py --dry-run
```

Печатает, что было бы отправлено, и ничего не отправляет.

## Ограничения

- GitHub запускает расписание с задержкой в несколько минут — для новостей это
  неважно.
- Если в репозитории 60 дней ничего не происходит, GitHub выключает расписание.
  Бот сам коммитит `state.json`, что обычно этого не допускает; если уведомления
  замолчали — зайдите в Actions и включите workflow обратно.
- Токен и chat id лежат в Secrets, в коде их нет. Публичный репозиторий для
  этого безопасен.
